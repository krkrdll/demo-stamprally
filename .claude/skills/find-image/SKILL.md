# find-image スキル

ユーザーが指定した画像をウェブ検索で見つけ、ローカルにダウンロードする。

## 手順

### 1. 引数の解釈

ユーザーのメッセージから以下を読み取る：

- **検索クエリ**：探したい画像の説明（例: "桜の木 フリー素材"）
- **保存先パス**：指定があればそのパス、なければ `public/images/<filename>` を使う
- **ファイル名**：指定があればそれ、なければ検索クエリから推測した英数字スネークケース名 + 拡張子

### 2. 画像を検索する

WebSearch ツールで画像の URL を探す。

検索クエリの組み立て方：
- ユーザーの説明をそのまま使う
- フリー素材・ライセンスフリーが望ましい場合は "site:unsplash.com" や "site:pixabay.com" などを加える
- 日本語クエリが来た場合は英語クエリも試す

検索結果から画像 URL を特定する基準：
- 直リンク可能な画像ファイル URL（`.jpg`, `.png`, `.svg`, `.webp` 等で終わるもの）を優先
- ページ URL しか得られない場合は WebFetch でページを取得し、`<img src>` や `<meta property="og:image">` から画像 URL を抽出する

### 3. 画像をダウンロードする

保存先ディレクトリが存在しない場合は先に `mkdir -p` で作成する。

```bash
curl -L -o "<保存先パス>" "<画像URL>"
```

- `-L` でリダイレクトに追従する
- ダウンロード後に `file <保存先パス>` でファイルタイプを確認し、HTML が返っていないか検証する

### 4. 結果を報告する

以下をユーザーに伝える：
- 保存先の相対パス
- 画像の出典 URL
- ファイルサイズ（`ls -lh` で確認）
- ライセンス上の注意点（分かる範囲で）

## 注意事項

- 著作権に注意する。商用利用不可のものをビジネス用途に使わないよう、ライセンスが不明な場合はユーザーに確認を促す。
- ダウンロードに失敗した場合（403, 404 等）は別の候補 URL を試す。
- 画像が大きすぎる（例: 10MB 超）場合はユーザーに確認してからダウンロードする。
- `public/` 以外のパスに保存する場合、`.gitignore` への追加が必要かをユーザーに確認する。
